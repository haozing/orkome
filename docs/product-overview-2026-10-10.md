## 1. 产品定位

**Orkome 是一个多智能体协作平台：人以"工作项"驱动工作，AI 智能体以"任务"执行工作；一个工作项由多个任务组成。**

它要解决的问题是：让 AI 智能体成为团队里可管理、可观察、可托付的"数字同事"，而不是聊天窗口里的一次性问答。三条产品主线：

1. **工作项是唯一的工作主轴**——所有产出（讨论、任务、文件、通知、自动化）都挂在工作项上，人和智能体在同一张看板上协作，过程可追溯。
2. **评论即指令**——在评论里 `@某个智能体`，它就会被唤醒并执行任务；发表前有实时预览，明确告诉你这条评论会唤醒谁、抑制谁。
3. **智能体是一等公民**——智能体有身份、权限、技能、模型配置、并发上限，可以组队（小队）、可以接入外部工具（MCP）、可以被定时唤醒（自动化）、也可以作为"数字同事"持续自主工作（外部运行时）。

产品以 SaaS 形态部署于 **orkome.com**（前后端同源），同时支持自托管（Docker + Postgres 即可启动）。

## 2. 目标用户与典型场景

| 用户 | 场景 |
|---|---|
| 团队负责人 | 把需求拆成工作项，指派给智能体执行，@提及追问，审批关键动作，看运行日志排查失败 |
| 个人开发者 | 用"我的工作"管理个人待办；给自己的 CLI 智能体（Codex、Claude Code 等）发 `ork_` 令牌，让它直接读写工作区 |
| 自动化运维者 | 配置自动驾驶：定时巡检、Webhook 事件触发，让智能体到点自动开工 |
| 智能体搭建者 | 维护智能体的模型、技能、MCP 工具与权限；组建多智能体小队分工协作 |

## 3. 核心概念速览

| 术语 | 含义 |
|---|---|
| 工作区（Workspace） | 数据与权限隔离边界，slug 全局唯一；一人可属多个工作区，顶栏一键切换 |
| 工作项（Work Item） | 工作主轴：标题/描述/验收标准/状态/优先级/受理人/父子关系/项目/标签/属性 |
| 任务（Task） | 智能体的一次执行：排队 → 派发 → 运行 → 完成/失败/取消，另有"延后"停车态 |
| 智能体（Agent） | 可配置的执行者：模型（OpenAI 兼容）、描述即 System Prompt、并发上限、可见性、开场白 |
| 小队（Squad） | 领队 + 成员的多智能体编排：Mode A 异步派工 / Mode B 同轮编队 |
| 技能（Skill） | SKILL.md + 文件树构成的知识包，绑定到智能体后按"渐进披露"注入 |
| MCP | 工具接入协议：工作区级/智能体级 MCP 服务器为智能体供工具；平台自身也能被外部客户端经 MCP 调用 |
| 唤醒规则（Wakeup） | 挂在工作项上的自动化：定时/事件/条件到期自动唤醒智能体继续干活 |
| 自动驾驶（Autopilot) | 工作区级自动化流程：cron 定时 / 入站 Webhook / 手动触发，两种执行模式（创建工作项 / 直接派发智能体） |
| 人工裁决（HITL） | 任务运行中可中断等待审批，用户批准/拒绝后继续或终止 |
| PAT | `ork_` 前缀个人访问令牌，供 CLI/程序调用 API 与 MCP |
| 数字同事（外部运行时） | dsh/claude/codex 等 CLI 智能体作为"客户"持续使用平台：看板 → 认领 → 执行 → 结算 |

## 5. 功能模块说明

### 5.1 账号与工作区

- **无密码登录**：任意邮箱 + 6 位验证码两步登录，首次登录即注册（验证码 10 分钟有效、5 次尝试上限）。
- **首次引导**：登录后无工作区则进入引导页——创建工作区（名称 + 自动建议的全局唯一 slug，创建者成为所有者）或凭分享码加入他人工作区。
- **多工作区**：顶栏切换器一键切换，所有数据随工作区隔离；侧栏可置顶常用工作项与会话。
- **成员管理**（API 完备，Web 暂无界面）：邮件邀请（7 天有效）、分享链接拉人；角色三档 **owner / admin / member**；移除成员即时吊销其全部会话与令牌；最后一名 owner 受保护，不可降职、移除或离开。
- **个人访问令牌（PAT）**：`ork_` 开头、仅存哈希、可设有效期（永久/30/90/180 天）、可续期吊销；明文仅在创建时展示一次。支持 CLI 扫码/换码登录。

### 5.2 工作项

- **创建**：弹窗内选项目、状态、优先级（无/低/中/高）、受理人（**成员与智能体混排选择**），支持"提交并继续"连续录入。
- **状态模型**：内置 7 状态（Backlog → To do → 进行中 → 审阅中 → 阻塞 → 完成/取消），归入未开始/进行中/已完成/已关闭四大类；**每个工作区可自定义状态**并拖拽排序。
- **浏览**：「全部工作」支持关键词搜索（标题/描述）+ 项目/状态/负责人筛选，筛选条件写入 URL 可分享；「我的工作」提供待办/已办/已创建/已订阅四个个人视角；另有表格视图、分组视图、受理人统计、子项进度、时间线、重复项检测（API 提供，Web 按需呈现）。
- **详情页**：标题栏一键切状态；右侧属性面板行内编辑（状态/优先级/受理人/起止日期/父工作项/项目/标签）；描述为富文本编辑，**自动保存 + 冲突时双版本对比**；四个 Tab（详细信息 / 子工作 / 任务 / 时间线）。
- **子工作项**：大任务拆子项，逐个派给智能体；从评论可一键生成子工作项并携带来源上下文。
- **结构化目录**：项目（可挂 repo/local_dir 资源）、标签、自定义属性（8 种类型：文本/URL/数字/勾选/日期/单选/多选/受理人）、个人视图与默认视图。

### 5.3 评论区——人机协作枢纽

- Markdown 评论、回复线程、@提及（**成员 + 智能体 + 小队 + @all**）、表情回应、已解决标记、软删除保留楼层。
- **触发预览**：输入 @ 后停顿即预览"发表后将唤醒：××智能体 / 已抑制：××"，预览与实际派发走同一路径，所见即所得。
- 触发决策有明确优先级：显式 @ > 回复智能体 > 线程根属主 > 受理人 > 小队领队；同一（工作项 × 智能体）的并发触发**自动合并为一个任务**而非重复排队。
- 自动订阅：创建者、受理人、评论者、被提及者自动订阅；可手动订阅/退订（含整棵子树）。

### 5.4 智能体

- **创建**：名称、描述（即 System Prompt）、模型供应商（OpenAI 兼容，支持自建网关/vLLM base_url）、API Key 凭据（密封存储、回显掩码）。
- **配置面**：
  - 模型：供应商/模型/base_url/凭据、**并发任务上限 1–50（默认 6）**、环境变量编辑器；
  - 技能：绑定/解绑/启停技能；
  - MCP：智能体专属 MCP 服务器（同名覆盖工作区级），可查看"生效配置合并视图"；
  - 权限：三档可见性——公开（全员可唤醒）/ 受限（白名单成员）/ 私有（创建者 + 白名单）；
  - 基本信息：开场白（最多 3 条，为直聊会话准备）。
- **生命周期**：归档后不再接受新任务（指派/@/唤醒均被拒，进行中任务跑完），可恢复；可一键取消其全部任务。

### 5.5 任务执行与监控

- **状态机（8 态）**：排队中 / 延后 / 已派发 / 运行中 / **待审批** / 已完成 / 失败 / 已取消。
- **过程可见**：每个任务有完整消息流（文本/工具调用/工具结果/审批请求/错误），前端实时展示；运行日志页可按状态与智能体筛选全部任务流水并查看执行转写。
- **人工裁决（HITL）**：智能体运行中可中断停车，用户批准（附注）继续或拒绝终止。
- **可控性**：排队/派发中的任务可取消；工作项可重跑（rerun）、可追加补充材料（supplement）；运行中的任务可被新评论"转向"（下一轮注入）。
- **可靠性**：失败自动重试（默认 2 次，网络/过载类 3 次）；心跳 150 秒判死、24 小时无进展自动挂起；崩溃后经事务性 outbox 重放不丢事件。
- **结果与质量**：任务结束自动生成 ≤500 字总结；抽样触发 LLM 质量评估（1–5 分 + 评语，不可用时降级为规则报告）并推送通知。
- **用量计量**：按 provider/model/token/成本记录到智能体（小队任务按成员拆分），小时级汇总供报表。
- **智能体内置工具**：改工作项状态、唤醒签到；小队领队专属：派工给成员、创建子工作项、记录评估。

### 5.6 小队（多智能体编排）

- 组成：**领队**（编排与派工者）+ 多个成员智能体（可附角色说明）；领队被 @ 或受派时负责分工与汇总。
- 两种协同模式：
  - **Mode A 异步派工**：领队给成员派任务，各自独立执行（分钟～天级），完成后自动唤醒领队汇总；
  - **Mode B 同轮编队**：成员作为领队的工具在同一轮内秒级协同，用量按成员拆分。
- 成员状态实时可见：执行中 / 排队中 / 空闲 + 活跃任务数。
- 删除小队需先清空成员且无活跃任务。

### 5.7 技能库

- 技能 = SKILL.md（YAML frontmatter 必含 name）+ 附属文件树。
- 导入方式：手工新建、从 URL 拉取（zip/tarball/裸 SKILL.md）、上传 zip（≤50MiB）；URL 来源可一键"重新拉取"刷新。
- 在线编辑：左侧文件树 + 右侧编辑器，可新建附属文件。
- 绑定智能体后以**渐进披露**注入：先给名称+描述摘要，需要时再展开全文，节省上下文。
- 导入有四重防护（路径穿越拒绝/二进制跳过/限额/秘密擦洗），读取校验失败即拒绝服务。

### 5.8 MCP——双向的工具生态

- **向内（智能体用工具）**：工作区级与智能体级 MCP 服务器（名称/URL/可选 Key/启用开关），同名时智能体级覆盖工作区级；客户端进程级缓存。
- **outward（外部客户端用 Orkome）**：MCP 页提供 Codex（config.toml）、Claude Code（.mcp.json）、通用客户端（Bearer）三段一键复制配置；首批工具：`list_work_items` / `get_work_item` / `create_work_item` / `add_comment` / `my_work`。服务端点 `<origin>/mcp` 标注"即将上线"。
- 访问凭据即 PAT（页面内直接管理）。

### 5.9 外部运行时——"数字同事"

定位（ADR 0009）：外部运行时（dsh / claude / codex 等 CLI 智能体）**是平台的客户，不是执行器**——像人一样持续使用平台。

- 接入三步：管理员创建 external 智能体 → 发放 `ork_` 凭据 → 运行时侧配置 MCP Streamable HTTP。
- 工作循环（client-kit/AGENTS.md）：看板 → 理解 → 认领 → 执行 → 结算 → 沟通。
- 9 个工具动词：list_my_work_items / get_work_item / get_task / get_task_messages / claim_task / report_progress / complete_task / fail_task / post_comment。
- 写权限围栏锁死在"自己的任务 + 评论"；附 orkome-loop.sh 参考监督器（轮询自己的工作项自动唤醒）。

### 5.10 自动化

- **唤醒规则（挂在工作项上）**：定时 / 事件 / 条件（边沿触发：条件由假变真才触发）/ 系统四类；到期自动唤醒智能体继续干活；可启停、改指令、手动"立即唤醒"、签到补回执。
- **自动驾驶（工作区级流程）**：触发器三种——cron 定时（带时区预览下次运行）/ 入站 Webhook（HMAC 签名校验、token 可轮换）/ 手动；执行模式两种——自动创建工作项 / 直接派发目标智能体或小队；有每日配额、运行历史、投递记录与重放。
- **熔断保护**：连续失败自动置停并展示原因，人工重新启用后恢复。
- **出站 Webhook（事件推送）**：订阅 5 类事件（task.completed / task.failed / work_item.created / work_item.updated / comment.created）推到自有 URL（SSRF 校验），支持签名密钥、投递历史、重放、测试事件。
- Web 端现状：自动化页仅提供管理（启停/立即触发/删除），**创建与编辑需经 API**。

### 5.11 通知

- 5 类通知：任务完成、任务失败、新评论、审批请求、评估报告。
- 顶栏铃铛：未读数 + 最近通知下拉，点击跳转关联工作项并自动已读；全站 WS 实时刷新。
- 通知中心：全部/未读/已归档三视图，单条与批量已读/归档。
- 偏好设置（API）：按来源类型 / 按工作项 / 按会话静音（支持通配）。

### 5.12 附件与文件

- 五类宿主：工作项 / 评论 / 聊天会话 / 聊天消息 / 任务；单文件 ≤100MiB，每宿主 ≤100 件/500MiB。
- 下载三模式：内联预览判定 / 代理 / **HMAC 签名直链**（绑定成员 + 有效期）；支持 Range 断点；SVG 强制下载防注入；删除时级联清理对象存储。
- 后端支持本地磁盘与 S3 兼容（MinIO 验证过）两种存储。

### 5.13 会话聊天（后端就绪、前端规划中）

后端已完备：与单个智能体的会话、消息历史与跨会话线程、置顶/归档/删除、未读、草稿中断恢复、快捷操作（一句话 prompt 模板，可对工作项一键运行）、会话内待办任务管理。前端 `/chat` 目前为占位页（规划：流式消息、WS chat 作用域）。

### 5.14 IM 渠道集成（框架就绪、适配器待接）

后端已建成完整框架：8 步入站管道（鉴权→去重→控制命令→媒体意图→工作项/会话调用→审计）、`/clear` `/new` `/task` 控制命令、突发消息合并去抖、标题推导 + LLM 润色、流式/分段回复投递、媒体待物化、渠道能力位掩码。**v1 尚未注册生产 IM 适配器**（飞书/Slack/Telegram 等为扩展点）。

### 5.15 插件系统（Pack）

- 形态（ADR 0008"双轨禁令"）：一方与三方插件走同一扇门——**独立部署的外部服务** + `pack.yaml` 声明（MCP 服务器 / 凭据 / 事件订阅 / UI 深链入口 / agents / skills），永不开放进程内嵌入。
- 安装：`pack-provision` CLI 读取 pack.yaml 向平台执行 install/uninstall（需 owner/admin PAT）。
- 前端表现：侧栏"Pack 扩展入口"动态渲染插件页面入口（一次性 ui_token 换取）。
- 纪律：插件数据永不进 Orkome 的 Postgres（"领域零规则"）。

## 6. 角色与权限

| 层 | 规则 |
|---|---|
| 工作区角色 | owner > admin > member；成员管理与模型凭据写入仅 owner/admin；最后一名 owner 不可降职/移除/离开 |
| 智能体可见性 | 公开（全员）/ 受限（白名单）/ 私有（创建者+白名单）；不可调用的智能体在触发时被压制并给出原因码 |
| API 访问 | 浏览器 Cookie 会话（CSRF 双绑定）或 PAT（仅存哈希）；被移除成员的会话与令牌 ≤10 分钟内全量吊销 |
| 数据隔离 | 所有业务查询带工作区谓词；工作区仅经 `X-Workspace-Id` 头解析（缺失 400 / 非成员 403） |
| 密钥安全 | 模型 API Key 以 AES-256-GCM 密封存储，任何响应中掩码为 `•••` |

## 7. 关键用户旅程

1. **上手**：邮箱验证码登录 → 创建/加入工作区 → 进入"全部工作"。
2. **派活给智能体**：新建工作项、负责人选某智能体 → 任务入队 → 详情页"任务"Tab 实时看状态与执行消息 → 完成后收到通知与 ≤500 字总结。
3. **评论追问**：评论区 @智能体（预览确认）→ 触发新任务；追问评论可"转向"正在运行的任务。
4. **审批**：任务转"待审批" → 批准继续 / 拒绝终止。
5. **组建团队**：建小队（领队 + 成员 + 编排指令，选 Mode A/B）→ @小队触发领队分工。
6. **装备智能体**：配模型与凭据 → 绑技能 → 挂 MCP 工具 → 设可见性与白名单。
7. **接入外部客户端**：MCP 页建 PAT → 复制 Codex/Claude Code 配置 → 客户端内用五件套工具操作工作区。
8. **自动化巡检**：建自动驾驶（cron/Webhook）→ 到点自动创建工作项或派发智能体 → 运行日志/通知跟踪 → 失败熔断人工恢复。

## 8. 安全与可靠性（用户可感知的部分）

- 无密码登录 + 登录端点 IP 限流 + 注册白名单（可配置允许的邮箱/域名）。
- 同源部署（orkome.com）下 Cookie/CSRF/WS Origin 零配置；跨域部署可配 CORS/WS 白名单。
- 所有用户可控出站目标（模型 base_url、MCP 端点）提交时过 SSRF 门（公网 HTTPS + 私网黑名单）。
- 附件持久化前秘密擦洗、读取时摘要校验（fail-closed）、签名直链防转发。
- 任务执行 at-least-once：事务性 outbox 崩溃重放、SKIP LOCKED 认领防重复执行、多副本调度去重（水平扩展安全）。
- 全链路 OTel 指标（任务状态转移、认领等待、outbox 积压、WS 连接等）。

## 9. 界面与本地化

- 桌面三栏布局（顶栏 + 固定侧栏 + 主区），**中/英双语**全量文案随切随生效，**亮/暗主题**一键切换并记忆。
- 实时性：单一 WebSocket 按工作区/用户/任务/会话作用域订阅，顶栏常驻连接状态徽章，断线指数退避重连。
- URL 即状态：筛选、Tab、展开的任务、通知视图均落在查询参数，可收藏/分享/刷新还原。

## 10. 当前限制与路线图

**已知限制（截至本文档基线）**

- 前端 `/chat` 为占位页（后端能力已齐备）；自动化流程无创建/编辑界面；成员/邀请管理无 Web 界面（均需经 API）。
- MCP 服务端点（outward）标注"即将上线"；渠道域无生产 IM 适配器。
- 中文语言包缺 `status.*` / `priority.*` 词条，中文界面下状态与优先级名回落英文。
- 桌面优先，无移动端专属导航。

**进行中的方向**

- `docs/ploykit-rebase-plan-2026-10-06.md`（Draft）：底座切换至 ploykit 框架，动机是商业化能力补齐（billing/quota/admin/audit/OAuth/DB 可吊销会话/声明式 RBAC）；七个业务域业务逻辑零改动，MCP 接入面与 `ork_` 凭据契约不动；绞杀者模式六阶段渐进替换。
- 规划中：直聊会话前端（流式消息）、渠道适配器、自动化创建界面、Agent Builder（构建草稿后端已就绪）。
