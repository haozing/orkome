# Orkome Web

Frontend foundation (SPA): React 19 + TypeScript (strict) + Vite 7 + Tailwind CSS v4 + Base UI v1 +
TanStack Router/Query. Backend contract: `../docs/route-compare/orkome_routes.txt` (static route
catalog) and `../cmd/orkome-server/router_contract_test.go` (enforced).

## i18n

UI text is bilingual (English/Chinese) via `react-i18next`. Locales live in `src/i18n/locales/en.ts` and `zh.ts`;
the language is detected from `localStorage["orkome.locale"]` → `navigator.language` (fallback English).
`LanguageToggle` in the app header switches at runtime. Tests pin English in `test/setup.ts`.

## Quick Start

```bash
pnpm install

# Terminal 1: backend (repo root)
go run ./cmd/orkome-server          # :8080

# Terminal 2: frontend
pnpm dev                               # :5173, same-origin proxy to the backend
```

Open http://localhost:5173 . The same-origin proxy lets cookie sessions, CSRF and WS Origin pass with
zero configuration; leave backend `CORS_ALLOWED_ORIGINS` empty. Override the backend address with the
`API_TARGET` env var (see `.env.example`).

### Recommended setup for smoke-testing a backend

```bash
# Note: if another service occupies :8080, start the current source orkome-server on another port
# with its own database:
export DATABASE_URL="postgres://postgres:orkome_e2e@localhost:54329/orkome_web?sslmode=disable"
export JWT_SECRET="<>=32 bytes>" ORKOME_DEV_VERIFICATION_CODE=123456 PORT=8081
go run ./cmd/migrate up && go run ./cmd/orkome-server

cd web && API_TARGET=http://localhost:8081 pnpm dev
# Log in with any email + verification code 123456 (fixed dev code, no email)
```

> Local cookie gotcha: cookies are shared per hostname across ports. If the browser has stale
> `_gorilla_csrf`/`orkome_csrf` from an old stack (with path shadowing), POSTs keep failing 403—
> visit via another host (e.g. `http://[::1]:5173`) or clear that host's cookies.

## Directory Layout

```
src/
  i18n/            # react-i18next setup + en/zh locale catalogs
  api/            # typed API modules per domain (mirror backend internal/<domain>; modeled from route contract + DTOs)
    identity.ts   #   login/session/workspace (send-code/verify-code/me/config/create workspace/join by share code)
  lib/
    api.ts        # fetch wrapper: CSRF bootstrap + X-Workspace-Id (injected provider) + error envelope → ApiError
    ws.ts         # WS client: event_id dedup, scoped-subscription refcount, exponential-backoff reconnect (zero app deps)
    ws-query-bridge.ts  # WS frames → TanStack Query invalidation bridge (rules registered per feature page)
    query.ts      # QueryClient factory (no retry on 4xx, no refetch on window focus—freshness comes from WS)
  realtime/       # wiring layer: app WS singleton (url resolver with ?workspace_id=)
  services/       # application coordination layer: cross store/cache/WS operations (e.g. switchWorkspace)
  hooks/ws.ts     # useWsStatus / useWsScope / useWsFrame
  stores/         # zustand: workspace (current workspace id, persisted), ui (theme)
  components/     # ui/ (Base UI + cva variant theme components: Button/Input/Badge/status components) and composites
                  # work-item/ (task panel/comment thread/timeline), markdown.tsx (react-markdown wrapper)
  routes/         # TanStack Router file routes: __root / login / onboarding / _app shell + pages
                  # work items: path node + index (quick create + recent list) + $id (detail: tasks/comments/timeline, tab and expanded task in URL search)
  styles/         # global.css (Tailwind v4 entry, .dark variant, base layer)
test/             # vitest + MSW (api client / WS client & hooks / invalidation bridge / components / layering rules)
```

Layered dependencies may only point downward (`test/arch/layering.test.ts` enforces it):
`routes → components → hooks → realtime → lib`, `api → lib`, `services` is the application coordination layer.

## Backend Integration Notes (read before writing features)

- **Auth**: HttpOnly cookie `orkome_auth`; `apiFetch` bootstraps CSRF automatically for mutating
  requests (GET /config returns the masked token → `X-CSRF-Token`), and stores new tokens carried by
  login/renewal responses.
- **Workspace**: `useWorkspaceStore` persists the current workspace id; `apiFetch` injects
  `X-Workspace-Id` into `/api/*` automatically (ADR 0005: id header as the single source, missing → 400).
- **Errors**: unified envelope `{error:{code,message,details?}}` → `ApiError`; codes are stable
  (`E_UNAUTHENTICATED`, `E_REVISION_CONFLICT`, …), branch on `code`.
- **Pagination**: cursor style `{items, next_cursor}`, paired with TanStack Query infinite queries.
- **WS**: single `/ws` endpoint; `wsClient.connect()` is called once when the `_app` shell mounts.
  workspace/user scopes subscribe on connect (cookie auth automatic); task/chat use
  `useWsScope('task', id)`. At-least-once delivery → the client dedups by `event_id` (built in);
  unknown frame types are silently ignored (built in).
- **Adding an API module**: model types in `src/api/<domain>.ts` after the backend
  `internal/<domain>/app` DTOs; call `api.get/post/...` inside functions; cover scenarios in
  `test/` using MSW `server.use()`.

## Conventions

- UI primitives always go through `src/components/ui/` (Base UI unstyled components + cva variants +
  Tailwind classes); do not hand-roll button/dialog styles in pages.
- URL is state: list/filter/pagination go into route search params (TanStack Router typed validation).
- Server state goes into TanStack Query; client global state is limited to WS status, current
  workspace, theme (zustand).
